# C：体检报告OCR测试与文档清单（今日合并版）

最初创建：2026-10-23；本次更新：2026-10-25。本文合并今天所有报告OCR改动的C待办。C负责测试、标注、缺陷复测及报告/PPT/视频/清单/披露等文本工作，A负责技术事实核实与后端修复。

## 一、可以使用的实现事实

- 后端按表头恢复项目、结果、单位和参考条件，支持不同表头写法、双栏、多表与单项目表，排除小结和节间元信息串入指标。
- 保留百分比/#后缀、下划线代码、结果末尾箭头、单侧参考条件及界限值。<0.2保留原文，不改成精确的0.2，不自动判正常。
- 对关键字段做有预算的局部识别；单位用同一OCR引擎的原图/放大/对比度增强视图交叉核对，不是独立模型集成。
- 通过图像裁剪恢复部分与名称粘连的数字；名称边界仍不确定时继续待核对，不猜测B12等名称中的数字为结果。
- 提供行距、序号和未配对文字的疑似漏项提示；不补造指标，提示可能误报或漏报。
- 识别失败时尝试保留分辨率的90/180/270度方向候选，并复用候选结果；有条件尝试表格裁剪/完整纸面四边形透视候选。候选改善不足或改变已有核对结果时回退原图。
- 证据映射回原图；上传、异步任务、历史与家属同步沿用持久化结果。处理版本report-ocr-2.2、字段版本3.0.0。
- 增加证据不足重拍闸门；闸门触发时不调用Qwen、不生成正式报告，返回原因和拍摄要求。少量项目不清楚时保留partial与待核对。

没有训练/微调OCR权重；没有接入PP-StructureV3；没有完成纸面弯曲矫正、同张照片混合方向分区识别或人工修改确认后再解读闭环。不得把上述未实现项写成已完成。

## 二、P0：人工标注与独立验收

- [ ] 人工逐项核对已有13张开发图片（最初8张加新5张）的项目名称/代码、结果、小数点、单位、参考条件、异常方向、遗漏和多余项。候选指标数不是正确项数。
- [ ] 这些图片已经参与调试，不再视为独立验收集。补充约20～30张脱敏报告，并留出未参与调参的一部分用于最终验收。
- [ ] 覆盖单/双栏、多表/单项目、不同列顺序、参考与单位粘连、缩写与名称粘连、阴阳性、<0.2界限值、缺参考条件、90/180度、斜拍、反光、截断与模糊。
- [ ] 对原图没有参考范围或被裁掉的区域标明“原件缺失/不可判”，不能查常识补进标准答案。
- [ ] 重点核对新图中的血小板/压积、HCT、胆红素/血脂以及CRP界限值，确认没有把序号、箭头、单位噪声或上限当成结果。
- [ ] 核对数字名称保护：B12/HbA1c/25-OH-D3不得拆成结果；恢复出的数字不能因与常见值接近就认定正确。

## 三、P0：重拍闸门与APP联合验收

后端闸门以证据充分程度判断，不声称能发现所有错误。当前操作阈值：没有文字/可靠表格、没有可用结果、没有高置信且配对明确的结果，或候选达到5项但其中不足一半有清晰且配对明确的结果时要求重拍。0.90及二分之一阈值均未经准确率校准，不代表概率。

- [ ] 清晰完整报告不应大量误触发重拍；部分缺单位、原件缺范围或个别字段不清时应尽量保留partial。
- [ ] 空白、无表头、严重模糊、结果列被裁掉时触发重拍；确认Qwen未调用、正式报告未生成。
- [ ] 同步HTTP422保留可读detail并返回retake字段；异步为failed且retake_required=true，error与拍摄要求可见。
- [ ] 与B检查弹窗只出现一次、重新拍摄/选择图片可用，普通网络故障和服务故障没有被错误提示为重拍。
- [ ] 异步失败即使有候选指标也不显示处理成功；权限、本人/家属/未授权访问、上传/历史/同步一致性继续回归。
- [ ] 测试旋转后原图框选是否准确；调试坐标不能直接绘制到原图。
- [ ] 对疑似漏项提示记录真假；表格分组留白不等同于真实漏项。

## 四、评测记录与统计

每项标注至少包含：样本编号、可见区域、名称/代码、结果原文与数值/界限类型、单位、参考条件原文及上下限、行归属、预期处理方式、实际结果和复测状态。

分别统计：字段完整匹配、数值准确、遗漏、多余、错行、单位/参考条件匹配、错误自动通过、待核对、重拍误报/漏报与耗时。记录样本量和分母；“程序已比较”不是“人工确认正确”。区分冷启动、普通原图、裁剪候选和方向回退的耗时。

规则/故障模拟测试、保存的真实文字框重放、重新调用真实OCR、真实API持久化、真实Qwen生成质量分别说明。接口测试使用解读占位时，不能称为真实模型解读通过。
