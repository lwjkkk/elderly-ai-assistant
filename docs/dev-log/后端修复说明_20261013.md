## 修复范围

本次只调整后端代码，没有修改 APK 或前端。目标是修复移动端上传、识别、导出以及家属端数据隔离相关问题。数据库表结构没有新增字段或表，不需要执行数据库迁移。

## 修复内容

### 1. OCR 初始化和移动端图片识别



* 将 OCR、PyTorch 的导入延迟到首次识别，避免 OCR 依赖加载失败时阻断其他 API 启动。

* Windows 环境下注册当前 Python/Conda 环境的 DLL 目录，改善 Paddle、PyTorch 运行库加载失败的问题。

* OCR 模型目录默认使用项目下的 `ocr_models`，而不是中文用户名目录或 D 盘根目录。可通过 `OCR_MODEL_DIR` 环境变量指定其他绝对路径。

* 增加启动时 OCR 自检：初始化识别器并用内存图像执行推理。OCR 自检失败会记录状态和错误，但不阻断其他 API。

* 区分服务端 OCR 故障和用户图片问题：依赖、模型或推理故障返回 HTTP 500；图片无法解码或没有识别到文字返回 HTTP 400。

* 兼容常见 JPEG、PNG、WebP 文件内容检测，允许移动端把图片 MIME 类型标为 `application/octet-stream`；保存文件扩展名由图片实际格式确定。

涉及文件：`config/settings.py`、`core/ocr.py`、`main.py`、`api/drugs.py`、`api/reports.py`、`api/vitals.py`。

### 2. 体检报告上传、指标和历史记录



* 修复报告上传接口的后端异常处理，OCR 环境故障不再误报为用户图片错误。

* 上传响应、报告历史和增量同步响应都返回 `metrics` 指标解析结果。

* 扩展参考范围解析，支持 `--`、`-`、`~`、`～`、`至` 等分隔形式，以及 OCR 常见的小数空格、逗号小数点错误。

* 能识别出项目和结果、但无法识别参考范围的指标标记为 `unparsed`（未能核对），不将其当成正常值。

* 将异常、正常、未能核对的指标分别提供给 AI 解读；如果 AI 总结与程序核对结果发生明显冲突，则隐藏不可靠总结并提示以报告原文和医生意见为准。

涉及文件：`api/reports.py`、`api/sync.py`、`core/report_parse.py`、`core/health_llm.py`、`db/schemas.py`。

### 3. 体征识别和 PDF 导出



* 修复血压识别结果中出现 `VALUE: NONE` 时被误认为识别失败的问题；只有模型完整输出 `NONE` 才按未识别处理。

* 支持识别血糖单位 `mg/dL` 并换算为 `mmol/L`，增加血压、血糖、心率和体重的合理范围校验。

* PDF 导出增加无数据提示、依赖缺失及生成异常的错误处理，并检查生成内容是否包含 PDF 文件头，避免把无效内容作为 PDF 返回。

涉及文件：`api/vitals.py`。

### 4. 家属本人数据和用药打卡



* 家属请求不带 `elder_id` 时，体征、报告、问诊、用药等本人数据归属当前家属账号。

* 家属请求指定老人 `elder_id` 时，仍须存在有效绑定；未绑定不能操作该老人的数据。

* 允许家属管理归属家属本人账号的用药记录，同时保留对其他账号的权限校验。

* 用药计划日期和打卡时间统一按北京时间计算；非计划时间、开始用药日期之前及未来时间点的打卡会被拒绝。今日用药清单和提醒任务也会跳过尚未开始的计划。

涉及文件：`api/meds.py`、`api/vitals.py`、`api/consults.py`、`services/scheduler.py`。

### 5. 家属端聊天记录隐私与查药总结



* 日常对话中被分类为查药的问题，同时写入查药记录，供查药记录接口展示。

* 这类对话记录标记为 `kind="chat"`。老人关闭 “对话记录同步家属” 后，家属的查药记录和同步接口不返回这类记录；老人本人仍可查看。独立的拍照查药、药名查药记录不受该开关影响。

* 调整查药 AI 提示词，分别处理药盒 OCR 文字和用户输入药名；OCR 没有可用文字时不调用 AI，避免依据空内容生成药品总结。

* 查药记录返回完整总结，避免固定长度截断。

涉及文件：`core/chat_summary.py`、`api/drugs.py`、`api/sync.py`。

## 部署说明



* 在部署设备安装项目 `requirements.txt` 中列出的依赖。OCR 需要对应的 PaddleOCR、PaddlePaddle、PyTorch 和图像处理依赖；PDF 导出需要 ReportLab、Matplotlib。

* 将 OCR 模型放在项目目录 `ocr_models` 下的 `det`、`rec`、`cls` 子目录，或通过 `OCR_MODEL_DIR` 指向已有模型目录。运行服务的账号需要能读取模型文件，并能写入模型目录（首次自动下载模型时）。

* 本次没有数据库迁移要求。APK 可继续使用现有接口路径；报告响应新增 `metrics` 字段，现有客户端不读取该字段时不影响原有字段。
