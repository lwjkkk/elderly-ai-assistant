# 后端待修改清单（2026-10-14 手机实测）

本清单对应当前前端版本。前端代码已接入以下接口约定，但本次远端提交不包含 Python 后端修改。

## 1. 双端家人消息持久化

- 新增 `family_messages` 表：`id`、`binding_id`、`sender_id`、`kind`、`content(JSON)`、`created_at`。
- 新增 `GET /api/messages/{binding_id}`，返回该绑定双方的历史消息，按创建顺序排列。
- 新增 `POST /api/messages/{binding_id}`，请求体为 `{ "kind": "text|health", "content": {...} }`。
- 两个接口都必须验证当前账号属于该条有效绑定；无权限返回 403。
- 消息必须存数据库，保证对方可收到且退出登录后历史记录仍存在。

## 2. 登录响应返回用户 ID

- `/api/auth/login`、`/api/auth/login_by_code` 和 `/api/auth/refresh` 返回体增加 `user_id`。
- 前端使用 `user_id` 区分发送方、接收方以及不同账号的 AI 对话本地缓存。

## 3. 隐私保护按开启时间生效

- `users` 表增加可空字段 `privacy_enabled_at`。
- 老人开启隐私保护时：`sync_summary_to_family=false`，并记录当前时间到 `privacy_enabled_at`。
- 老人关闭隐私保护时：`sync_summary_to_family=true`，并清空 `privacy_enabled_at`。
- 家属读取 `/api/chat/summaries`、`/api/sync` 和 `/api/drugs/records` 时：
  - 开启隐私前生成的对话摘要和 `kind=chat` 查药记录继续返回；
  - 开启隐私后生成的记录不返回；
  - 不删除任何历史数据。
- 老人本人读取自己的记录时不受该过滤影响。

## 4. 咨询录音访问权限

- 家属本人上传的录音归属家属本人，不应要求该家属与自己建立绑定。
- 已绑定家属读取长辈录音时，只要录音所属老人和当前家属存在有效绑定即可播放。
- `GET /api/consults/audio/{filename}` 必须支持：录音所有者本人、与所属老人有效绑定的家属。
- 未登录返回 401，无权限返回 403。
- `doctor` 字段当前由前端用作咨询标题，`hospital` 字段用作地址，两者需在列表接口原样返回。

## 5. 体征拍照 OCR 兜底

- `/api/vitals/recognize` 在 OCR 已识别到数字、但大模型返回 `NONE` 或格式异常时，应直接从 OCR 文本兜底解析。
- 血压可识别类似 `SYS 139 DIA 85 PUL 72`，返回 `type=bp`、`systolic=139`、`diastolic=85`。
- 血糖、心率、体重在提供 `vital_type` 时按对应合理范围提取数值。
- OCR 服务故障返回 500；照片确实没有有效数字才返回 400。

## 6. 数据库迁移

- 启动时幂等创建 `family_messages` 表。
- 对旧数据库幂等补充 `users.privacy_enabled_at DATETIME`。
- 不清理现有消息、聊天摘要、查药记录和咨询录音。

## 验收标准

- 老人和家属互发文字后，对方 3 秒内刷新可见，双方重新登录后仍存在。
- 非绑定账号访问会话或录音返回 403。
- 开启隐私后，家属仍能看到开启前摘要，看不到开启后新摘要。
- 家属本人录音无需绑定即可回放；绑定家属可以回放长辈录音。
- 常见血压仪照片在大模型结构化失败时仍可得到血压数值。

## 2026-10-15 前端长按删除与头像显示所需接口

前端已接入以下接口，但当前远端后端尚未提供，需合并本地实现后再部署：

- `DELETE /api/vitals/{vital_id}`：仅允许记录所有者删除本人记录。
- `DELETE /api/reports/{report_id}`：仅允许所有者删除，并同步清理上传图片。
- `DELETE /api/consults/{consult_id}`：仅允许所有者删除，并同步清理录音文件。
- `GET /api/bind/list` 每项增加 `other_avatar`，值为绑定对象的 `avatar_url`，供家人互动页显示真实头像。

前端删除入口采用长按记录弹出黑白确认框；绑定长辈的只读视图不显示删除入口。
