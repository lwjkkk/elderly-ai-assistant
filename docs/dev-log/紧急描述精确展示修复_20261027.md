# 紧急描述精确展示修复

> **历史版本记录**：保留当时的实现、测试或操作说明；当前配置与操作以主分支最新运行说明和实际接口为准。

日期：2026-10-27。前端基线 `main/ddc25cd`，后端基线 `backend/ae4f544`。参考本地 B/C 紧急提醒与语音合并清单，补充处理用户提出的“描述与提示症状不一致”问题。

## 原因与修改

原实现把多个表现归入同一风险类别，再把类别标签当成用户报告的症状。例如 `chest_pain` 同时覆盖疼痛和发闷，原标签为“胸痛胸闷”；家属卡片又用“老人提到”介绍该标签。通用急救前缀还列举了一组症状，容易与本次实际描述混淆。

本轮对全部 9 类风险统一处理，不做单个词语替换：

- `reported_question` 独立携带完整原话，保留主体、部位、性质、程度、时间、数字、多个症状和否认句。`emergency_types` 保留既有分类键；`emergency_labels` 使用“胸部不适相关危险信号”等类别文案，规则与家属消息复用同一份文案。
- 聊天红色横幅和老人／家属双视图分别展示“您描述”和“提醒类别”。本机聊天以实际提交文本为准，防止旧服务端回显错误描述；症状自查也展示实际提交文本。
- 家属会话卡片和首页弹窗分别展示“原话”和“提醒类别”。后台保存完整 `reported_question`，原 `question[:200]` 为旧客户端保留；新客户端优先读取完整字段，避免截掉长描述末尾的否认或时间条件。历史消息没有新字段时回退旧字段，不能恢复以前已截掉的内容。
- 通用紧急前缀保留 120／急诊动作，去掉与本次描述无关的示例症状；症状自查和双视图提示词要求忠实保留原意，不补造或替换症状。

例如“我心脏疼，没有胸闷，刚才开始的”完整展示为原话；“胸部不适相关危险信号”只用于提醒类别。同一机制覆盖呼吸、意识／晕厥、卒中、出血、气道梗阻、头痛、过敏和其他风险类别。

## 分支与兼容

`main` 提交前端、主线接口兼容及专项测试；主线原先缺少的口语和当前／否认／历史上下文快速规则取自已核对的后端版本。`backend` 在独立工作树中基于最新运行分支提交接口、症状自查快照、家属消息和提示词修改，保留已有的限时语义筛查、权限重查和持久化去重。

本轮不整体合并两个已分叉分支的知识库、OCR 等历史差异。无数据库列变更，原话保存在已有 JSON 字段；家属授权和去重策略继续生效。语音仍须核对后发送，“原话”指最终提交文本，不代表 ASR 与实际口述必然一致。
