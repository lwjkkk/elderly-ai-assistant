## 一、为什么需要免责声明

本产品涉及**健康医疗、用药指导、症状自查、体检报告解读**等敏感领域。根据《中华人民共和国基本医疗卫生与健康促进法》《互联网诊疗管理办法》等相关法规，AI 产品不得替代医生进行疾病诊断和处方。因此，所有涉及健康医疗的功能必须在显著位置展示免责声明，明确告知用户：**AI 输出仅供参考，不能替代医生诊断**。

---

## 二、免责声明文案（后端已实现）

后端在 `core/disclaimer.py` 中定义了两个统一常量，所有医疗相关接口响应中必须包含 `disclaimer` 字段。

### 2.1 通用健康免责（HEALTH_DISCLAIMER）

**使用场景**：体征记录、体检报告解读、症状自查、问诊记录等健康类功能。

**固定文案：**

```
以上内容仅为健康科普与信息整理，不能替代医生面诊，不构成疾病诊断或用药建议。如有不适，请及时咨询医生或拨打急救电话。
```

### 2.2 药品解读专用免责（DRUG_DISCLAIMER）

**使用场景**：拍照查药、按药名查询药品常识。

**固定文案：**

```
本结果仅用于帮助理解药品说明书，不构成用药建议或诊疗诊断；具体用法用量请遵医嘱或咨询药师，切勿自行增减或停药。
```

### 2.3 日常问答免责（chat 接口）

**使用场景**：手机操作、便民办事、生活常识等非医疗类问答。

**固定文案（在 `core/agent.py` 中定义）：**

```
以上内容仅供参考，具体操作请以实际界面为准。如有疑问请咨询子女或社区工作人员。
```

## 四、前端展示规范（给 B）

### 4.1 常驻底部提示条

所有**医疗健康相关页面**（用药、体征、查药、体检报告、症状自查）底部必须常驻免责声明提示条：

- **位置**：页面底部，固定不随滚动消失
- **样式**：浅灰色背景，14-16号字，深灰色文字
- **文案**：`内容仅供参考，不能替代医生诊断`
- **高度**：不超过40px，不遮挡主要操作按钮

### 4.2 首次进入弹窗

用户**首次进入医疗模块**（用药/体征/查药/体检/症状自查中任意一个）时，弹窗展示完整免责声明：

- **标题**：`温馨提示`
- **内容**：完整的通用健康免责文案
- **按钮**：`我知道了`（唯一按钮，点击后关闭，7天内不再弹出）
- **不可关闭**：弹窗必须点击按钮确认，不可点击空白处关闭

### 4.3 高风险警告（症状自查 red 等级）

当症状自查返回 `risk = "red"` 时，除了常规免责声明外，必须：

- 页面背景变为浅红色
- 顶部显示红色大字警告：`⚠️ 建议立即就医或拨打120`
- 提供`拨打120`按钮（点击直接跳转到拨号界面）
- 不允许折叠或隐藏此警告

### 4.4 药品解读页面

查药结果页面必须：

- 在结果底部展示药品专用免责声明
- 明确标注`AI解读仅供理解说明书，具体用药请遵医嘱`
- 不出现"推荐服用""建议停药"等引导性表述

## 五、AI 提示词中的伦理约束（A 已实现）

### 5.1 药品科普提示词（`api/drugs.py`）

```
你是面向老年人的药品科普助手。请根据药盒上识别到的文字，用大白话分三部分说明：
一、这个药主要是做什么的（作用）；
二、使用时要注意什么、哪些情况或人群需要特别小心（禁忌）；
三、可能出现哪些不适（副作用）。
要求：语言通俗、句子简短、不制造恐慌；识别信息不足就如实说明看不懂；
严禁给出疾病诊断、处方、具体剂量调整、停药或换药建议，并提醒以医嘱和说明书为准。
```

### 5.2 适老化系统提示词（`core/prompt.py`）

```
你是一个帮助老年人解决手机操作和数字生活问题的智能助手。
回答要求：
1. 语言通俗易懂，像跟长辈说话一样，不要用专业术语
2. 步骤要拆得很细，每一步只说一个动作
3. 用"第一步、第二步、第三步"这样的格式
4. 如果涉及按钮名称，用「」标出来
5. 回答要简短，不要啰嗦
6. 结尾提醒老年人操作时如果找不到按钮，可以问问身边的年轻人
```

### 5.3 症状自查提示词（`core/health_llm.py`）

症状自查的 AI 提示词必须包含以下约束：
- 不得给出明确的疾病诊断
- 不得推荐具体药物
- 风险分级必须保守（不确定时倾向于更高风险等级）
- 高风险情况必须明确建议就医或拨打120

## 六、知识库内容合规要求（C 负责）

### 6.1 health 知识库

所有 health 目录下的知识文章必须：

- ✅ 仅做健康科普，不做疾病诊断
- ✅ 涉及用药时注明"具体用药请遵医嘱"
- ✅ 涉及急救时给出正确的急救步骤和120提示
- ❌ 不得出现"包治""根治""特效"等绝对化表述
- ❌ 不得推荐具体药品品牌或厂家
- ❌ 不得出现替代医生的表述

### 6.2 违禁词扫描清单（Day6 联调时用）

知识库和 AI 输出中禁止出现以下词汇：

| 类别 | 违禁词示例 |
|---|---|
| 绝对化疗效 | 包治、根治、痊愈、特效、100%有效、永不复发 |
| 诊断替代 | 你得了XX病、确诊为、这就是XX病 |
| 处方建议 | 建议服用XX药、吃XX药就好、可以停药了、把药减半 |
| 医疗承诺 | 保证治好、无效退款、几天见效 |
| 虚假宣传 | 国家级、最高级、最佳、第一品牌 |

> Day6 联调时，C 需要用 `verify_validation.py` 或手动扫描知识库和 AI 输出，确保不包含违禁词。

## 七、隐私保护要求

### 7.1 用户数据

- 手机号在 API 返回中脱敏（如 `138****8000`），绑定列表中已实现 `other_nickname` 替代手机号展示
- 密码仅存储 bcrypt 哈希，不可逆
- 健康数据（体征、用药、体检报告）按 `elder_id` 隔离，家属只能访问已绑定老人的数据

### 7.2 录音和图片

- 问诊录音和体检报告图片存储在本地 `uploads/` 目录
- 访问路径虽然不需要鉴权（`/api/consults/audio/{filename}`、`/api/reports/image/{filename}`），但文件名使用 UUID，不可枚举
- M5 上线时建议为这些静态资源添加鉴权中间件

### 7.3 AI 调用

- 开发环境使用本地 Ollama 部署的开源模型（qwen2:7b），数据不出本地
- 如切换到云端 API（通义千问），需在隐私政策中告知用户数据将上传至第三方

## 八、答辩时的合规话术

答辩时如被问到医疗合规问题，可使用以下表述：

> "我们的产品定位是**健康科普和信息整理助手**，不是医疗诊断工具。所有涉及健康医疗的功能都有明确的免责声明，AI 提示词中严格约束不做疾病诊断和处方建议。症状自查采用保守的风险分级策略，高风险情况明确引导用户就医。我们的目标是帮助老年人更好地理解健康信息、管理日常健康数据，而不是替代医生。"
