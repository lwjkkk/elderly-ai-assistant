## 已复现并修复的问题

| 问题 | 修复与结果 |
| --- | --- |
| 多轮草稿只补时间不生效 | 时间独立提取，支持仅补时间、明确按现在记录；补充完整原话 |
| 高压单字段纠错未覆盖旧值 | 明确字段纠正覆盖旧字段；切换体征类型清理旧数值和单位 |
| 时间文本误作体征值、体征尾数误作分钟 | 补数值使用完整表达匹配；分钟只读取紧随时刻的内容；修正下午/晚上时刻 |
| 草稿续轮可能覆盖并发确认/取消 | 续轮基于脱离 ORM 跟踪的快照合并，使用数据库版本条件写回，冲突返回 409 |
| 已确认会话并发使用新幂等键可能报错 | 捕获唯一键竞争并返回原体征；重放时读取当前通知状态 |
| 家属本人创建的草稿无法再读/确认 | 本人归属优先，家属本人记录无需绑定自己；他人记录继续校验绑定 |
| `subject_confirmed=null` 可导致数据库错误 | 输入阶段明确拒绝空确认状态，不再进入数据库错误路径 |
| 通知重试忽略后续解绑或撤回分享 | 每次发送前重新核查绑定、年龄、共享和来源事件，失效任务标为 suppressed |
| 多个通知消费者可能重复发送 | 数据库条件领取任务；新增 claimed_at，5 分钟未结束的领取可恢复；记录失败独立重试 |
| 接口和后台任务绕过请求数据库使用全局库 | 体征通知、问答摘要和紧急事件使用请求绑定的数据库会话工厂；避免隔离测试或不同部署库串库 |
| 紧急事件线程依赖请求 ORM 对象 | 线程只接收稳定账号 ID，再在自身会话中读取当前用户和授权 |
| 报告无单位、反向范围、多项挤一行仍作确定判断 | 保留 OCR 原文并降为 unparsed；返回 verification_reason 和 parser_version=2.2.0 |
| 报告血压 120/80 被展示成单值 80 | 双值保存为 result_text=120/80，result=null，保留待人工分项核对状态 |
| 三段式旧客户端字段不全、就医条件被截断 | 同时保留 concern/meaning/next_step 与 conclusion/advice 别名；老人版完整保留 seek |
| 健康问题被第一条生活目录来源改成生活问答 | 明确健康问题保持 health；胸痛等红旗问题优先走健康分流；健康免责声明独立返回 |
| 手机操作被强制套医疗三段式 | 操作类保留原始回答及步骤，不加入医疗解释或就医提醒 |
| 饮食问题混入服药/节日片段，红包问题混入付款码 | 召回阶段同时检查明确主题、疾病及正文子主题；增加铁路购票、校准保养等边界；修正“机动车/动车”误匹配 |
| UTC 落库后查询窗口和趋势日期仍按服务器本地时间处理 | 查询窗口统一 UTC；趋势按北京时间日期分组，覆盖跨午夜样例 |

- 部署时使用项目正常启动流程运行 init_db，再启动消费者。更新前备份数据库；回滚时先停止服务，保留新增表列与历史数据，恢复对应代码及必要的部署前备份，避免手工删除健康记录。
- 通知消费者使用数据库领取和超时恢复。真实外部提供商未来仍应支持幂等请求 ID，以处理“提供商已接受、进程在保存结果前崩溃”的重复投递窗口；本轮不能承诺外部通道严格恰好一次。
