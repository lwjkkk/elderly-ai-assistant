## 1. P0：恢复真实 OCR 模型加载

**位置：** `core/ocr.py`、`config/settings.py`，后端运行环境。

**已复现：** 检测模型文件存在，但 Paddle 初始化预测器报错：

```text
Cannot open file C:/Users/李文君/.paddleocr/whl/det/ch/ch_PP-OCRv4_det_infer/inference.pdmodel
```

因此真实图片尚不能稳定完成 OCR → 大模型 → 结构化响应。中文路径兼容是怀疑原因，需要通过纯英文目录对照验证，不能只检查模型文件是否存在。

**修改要求：**

- 提供 `OCR_MODEL_DIR` 配置，将检测、识别、方向分类模型放到纯英文绝对路径，例如 `D:/ocr_models`；显式传入 `det_model_dir`、`rec_model_dir`、`cls_model_dir`。
- 启动检查依赖、模型文件、预测器初始化和测试图识别；环境失败应返回明确服务错误，不应统一提示用户“重拍照片”。
- 查药、报告上传在 OCR 为空时停止生成，避免模型自行补充不存在的内容。

**验收：** 真实药盒、血压计、体检单三类图片均能返回非空识别文字；模糊图/无文字图明确失败；成功文字确实进入模型，返回字段与前端契约一致。

## 2. P0：体征识别不要因不适用字段为 NONE 而拒绝合法数据

**位置：** `api/vitals.py` 的 `recognize_vital()`、`_parse_vitals_llm()`。

**已复现模型输出：**

```text
TYPE: bp
SYSTOLIC: 135
DIASTOLIC: 85
VALUE: NONE
UNIT: mmHg
CONFIDENCE: 1.0
```

解析函数可以得到正确的血压字段，但路由的 `if "NONE" in llm_out.upper()` 把整条结果判为失败，返回 400。

**修改要求：**

- 只将独立的失败标记视为失败，例如 `llm_out.strip().upper() == "NONE"`，不能对子串做整体判断。
- 按 type 校验必需字段：bp 必须有 systolic/diastolic；bs/hr/weight 必须有 value；不适用字段允许为空。
- 优先使用 JSON + Pydantic 校验；校验数值与单位，不能静默填充猜测值。

**前端需要：** `type`、`systolic`、`diastolic`、`value`、`unit`、`confidence`、`ocr_text`。识别只回填表单，确认后另调保存接口。

**验收：** 上述输出返回 200，135/85 保持不变；独立 NONE 返回明确失败；覆盖四种体征和血糖单位换算。

## 3. P0：报告参考范围解析与解读结果必须一致

**位置：** `core/report_parse.py`、`core/health_llm.py`、`api/reports.py`、`db/schemas.py`。

**已复现输入：**

```text
空腹血糖 GLU 5.1 mmol/L 参考范围 3.9-6.1
总胆固醇 TC 6.2 mmol/L 参考范围 2.8-5.2
```

当前范围正则只支持 `--`，单横线范围没有被解析；模型随后输出“均在正常范围内”。HTTP 200 不代表解读正确。

**修改要求：**

- 支持实际报告常见的 `-`、`--`、`~`、`～`、`至` 等范围格式；覆盖单位、序号、错行和 OCR 数字空格。
- 未解析成功时明确返回“未能核对”，禁止把缺失核对结果当作全部正常。
- 程序核对异常项后，模型解释必须与其一致；建议响应增加 `metrics` 和解析状态，前端不用自由文本自行推测数值状态。

**验收：** 上述 TC 6.2 大于给定上限 5.2，程序与解读必须一致；覆盖正常、偏高、偏低、无法识别和错行报告。
