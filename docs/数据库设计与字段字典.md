## 一、概述

### 1.1 技术栈

| 项目 | 值 |
|---|---|
| 数据库 | SQLite 3（开发/演示），可无缝切换 MySQL |
| ORM | SQLAlchemy 2.0 |
| 数据校验 | Pydantic v2（`db/schemas.py`） |
| 建表方式 | 启动时 `Base.metadata.create_all()` 自动建表 |
| 数据库文件 | `elderly.db`（项目根目录，`db/database.py` 第9行定义） |

### 1.2 命名规范

| 对象 | 规范 | 示例 |
|---|---|---|
| 表名 | 小写蛇形，复数 | `users`、`medication_logs` |
| 字段名 | 小写蛇形 | `elder_id`、`created_at` |
| 主键 | `id`，自增整数 | `id` |
| 外键 | `{关联表单数}_id` | `elder_id`、`medication_id` |
| 时间字段 | `created_at` / `updated_at` / `measured_at` | DATETIME |
| 状态字段 | 字符串枚举，小写 | `status = "active"` |

### 1.3 通用约定

- **主键**：所有表 `id` 为 `Integer`，自增，带索引。
- **时间**：`created_at` 使用 `server_default=func.now()`，数据库层默认当前时间（UTC）。
- **删除策略**：**物理删除**（A 当前实现未使用软删除 `is_deleted` 字段）。删除药品时级联删除其打卡记录。
- **JSON 字段**：`medications.times` 使用 SQLAlchemy `JSON` 类型，直接存储 Python 列表。
- **外键约束**：所有 `elder_id`、`medication_id` 等均声明 `ForeignKey`。

### 1.4 数据分区与权限

- 所有健康表按 `elder_id` 分区，查询必须带 `elder_id` 条件。
- 家属必须与老人有 `family_bindings.status = "active"` 的绑定关系才能操作。
- 老人操作自己的数据时，`elder_id` 自动取当前用户 ID。

### 2.1 users — 用户表

**用途**：存储老人和家属的账号信息，用 `role` 字段区分身份。

| 字段名 | 类型 | 约束 | 必填 | 说明 | 示例 |
|---|---|---|---|---|---|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | 是 | 用户ID | `1` |
| role | VARCHAR(10) | NOT NULL | 是 | 角色：`elder`（老人）/ `family`（家属） | `"elder"` |
| phone | VARCHAR(20) | UNIQUE NOT NULL INDEX | 是 | 手机号，作为登录账号，唯一 | `"13800138000"` |
| password_hash | VARCHAR(255) | NOT NULL | 是 | 密码哈希（bcrypt），禁止明文 | `"$2b$12$..."` |
| nickname | VARCHAR(50) | NOT NULL | 是 | 昵称，绑定后双方可见 | `"张爷爷"` |

**索引：**

| 索引名 | 字段 | 类型 | 说明 |
|---|---|---|---|
| ix_users_id | id | PRIMARY | 主键 |
| ix_users_phone | phone | UNIQUE | 手机号唯一，登录查询 |

**枚举值：**

| 字段 | 取值 | 含义 |
|---|---|---|
| role | `elder` | 老人 |
| role | `family` | 家属（子女） |

**与代码对应**：`db/models.py → class User`  
**接口 Schema**：`UserCreate`（注册请求）、`UserOut`（返回，不含密码）、`LoginRequest`、`Token`

### 2.2 family_bindings — 家属绑定表

**用途**：记录老人与家属的绑定关系。老人生成邀请码（pending），家属输入邀请码确认（active）。

| 字段名 | 类型 | 约束 | 必填 | 说明 | 示例 |
|---|---|---|---|---|---|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | 是 | 绑定记录ID | `1` |
| elder_id | INTEGER | FOREIGN KEY(users.id) NOT NULL | 是 | 老人用户ID | `1` |
| family_id | INTEGER | FOREIGN KEY(users.id) NULLABLE | 否 | 家属用户ID；pending 状态时为 NULL，接受绑定时填入 | `2` |
| status | VARCHAR(20) | NOT NULL DEFAULT 'pending' | 是 | 绑定状态 | `"active"` |
| invite_code | VARCHAR(20) | NOT NULL INDEX | 是 | 6位邀请码（大写字母+数字） | `"A3B9X2"` |
| created_at | DATETIME | SERVER DEFAULT NOW() | 是 | 记录创建时间（即邀请码生成时间） | `"2026-10-02T10:00:00"` |

**索引：**

| 索引名 | 字段 | 类型 | 说明 |
|---|---|---|---|
| ix_family_bindings_id | id | PRIMARY | 主键 |
| ix_family_bindings_invite_code | invite_code | NORMAL | 邀请码查询（接受绑定时用） |

**枚举值：**

| 字段 | 取值 | 含义 |
|---|---|---|
| status | `pending` | 待绑定（邀请码已生成，家属尚未确认） |
| status | `active` | 已绑定（家属确认，双方可互看数据） |
| status | `unbound` | 已解绑 |
| status | `expired` | 邀请码已过期（30分钟未使用自动标记） |

**业务规则：**
- 邀请码有效期 **30 分钟**（`INVITE_CODE_EXPIRE_MINUTES = 30`），超时后标记为 `expired`。
- 每个老人同一时间只有一条 `pending` 记录，重新生成邀请码会覆盖旧记录。
- `family_id` 在 pending 阶段为 NULL，家属接受绑定时才填入。
- 解绑功能当前未在接口中实现（status 预留了 `unbound`）。

**与代码对应**：`db/models.py → class FamilyBinding`  
**接口 Schema**：`InviteOut`、`BindAccept`、`BindingOut`

### 2.3 medications — 用药计划表

**用途**：记录给某位老人录入的药品及服药时间安排。

| 字段名 | 类型 | 约束 | 必填 | 说明 | 示例 |
|---|---|---|---|---|---|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | 是 | 药品ID | `1` |
| elder_id | INTEGER | FOREIGN KEY(users.id) NOT NULL | 是 | 所属老人ID | `1` |
| created_by | INTEGER | FOREIGN KEY(users.id) NOT NULL | 是 | 录入者用户ID（老人自己或绑定家属） | `1` |
| name | VARCHAR(100) | NOT NULL | 是 | 药品名称 | `"硝苯地平缓释片"` |
| dosage | VARCHAR(50) | NOT NULL | 是 | 剂量/规格，如 `"1片"` / `"100mg"` | `"20mg"` |
| frequency | VARCHAR(50) | NOT NULL | 是 | 频次，自由文本，如 `"每日1次"` / `"每日3次"` | `"每日2次"` |
| times | JSON | NOT NULL DEFAULT list | 是 | 服药时间点列表，格式 `HH:MM`，至少1个 | `["08:00","20:00"]` |
| created_at | DATETIME | SERVER DEFAULT NOW() | 是 | 创建时间 | `"2026-10-02T12:00:00"` |

**索引：**

| 索引名 | 字段 | 类型 | 说明 |
|---|---|---|---|
| ix_medications_id | id | PRIMARY | 主键 |

> **注意**：A 当前未给 `elder_id` 加单独索引，查询用药列表时是全表过滤。数据量小不影响，M5 可补充 `ix_medications_elder (elder_id)` 索引。

**times 字段说明：**
- 使用 SQLAlchemy `JSON` 类型，SQLite 原生支持 JSON。
- 存储为 JSON 数组，如 `["08:00", "12:00", "20:00"]`。
- 接口请求/响应中直接为字符串数组，无需手动序列化。

**与代码对应**：`db/models.py → class Medication`  
**接口 Schema**：`MedicationCreate`、`MedicationUpdate`、`MedicationOut`、`TodayMedication`

### 2.4 medication_logs — 服药打卡记录表

**用途**：记录每个药品在某天某个时间点的服药状态。

| 字段名 | 类型 | 约束 | 必填 | 说明 | 示例 |
|---|---|---|---|---|---|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | 是 | 打卡记录ID | `1` |
| medication_id | INTEGER | FOREIGN KEY(medications.id) NOT NULL | 是 | 关联用药计划ID | `1` |
| elder_id | INTEGER | FOREIGN KEY(users.id) NOT NULL | 是 | 所属老人ID（冗余，方便按老人查询） | `1` |
| date | VARCHAR(10) | NOT NULL INDEX | 是 | 日期，格式 `YYYY-MM-DD`（字符串存储，非 DATE 类型） | `"2026-10-02"` |
| slot | VARCHAR(10) | NOT NULL | 是 | 时间点，格式 `HH:MM`，对应 medications.times 中的值 | `"08:00"` |
| status | VARCHAR(10) | NOT NULL DEFAULT 'pending' | 是 | 打卡状态 | `"taken"` |
| updated_at | DATETIME | SERVER DEFAULT NOW() ON UPDATE NOW() | 是 | 最后更新时间 | `"2026-10-02T08:05:00"` |

**索引：**

| 索引名 | 字段 | 类型 | 说明 |
|---|---|---|---|
| ix_medication_logs_id | id | PRIMARY | 主键 |
| ix_medication_logs_date | date | NORMAL | 按日期查询 |

**枚举值：**

| 字段 | 取值 | 含义 |
|---|---|---|
| status | `pending` | 待服（未打卡，今日清单中未打卡的时间点返回此状态） |
| status | `taken` | 已服（用户点击打卡后写入/更新） |
| status | `missed` | 漏服（预留，当前接口未自动标记漏服） |

**业务规则：**
- 打卡接口 `POST /api/meds/checkin` 是 **upsert** 逻辑：如果该药品+日期+时间点已有记录则更新 status 为 `taken`，否则插入新记录。
- `date` 字段用 `VARCHAR(10)` 而非 `DATE` 类型，因为 SQLite 的 DATE 类型处理较繁琐，字符串比较同样可行。
- `elder_id` 冗余存储，避免查询时 JOIN medications 表。
- 删除药品时，A 的代码会先删除该药品的所有打卡记录（`db.query(MedicationLog).filter(...).delete()`），再删除药品。

**与代码对应**：`db/models.py → class MedicationLog`  
**接口 Schema**：`CheckInRequest`、`LogOut`、`SlotStatus`

### 2.5 vitals — 体征记录表

**用途**：存储血压、血糖、心率、体重等体征测量数据。

| 字段名 | 类型 | 约束 | 必填 | 说明 | 示例 |
|---|---|---|---|---|---|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | 是 | 记录ID | `1` |
| elder_id | INTEGER | FOREIGN KEY(users.id) NOT NULL | 是 | 所属老人ID | `1` |
| type | VARCHAR(10) | NOT NULL | 是 | 体征类型 | `"bp"` |
| systolic | INTEGER | NULLABLE | 血压时必填 | 收缩压（高压），单位 mmHg；非血压类型为 NULL | `145` |
| diastolic | INTEGER | NULLABLE | 血压时必填 | 舒张压（低压），单位 mmHg；非血压类型为 NULL | `90` |
| value | VARCHAR(20) | NULLABLE | 非血压时必填 | 通用数值（字符串存储）；血压类型为 NULL | `"6.8"` |
| measured_at | DATETIME | SERVER DEFAULT NOW() | 是 | 测量时间，默认当前时间 | `"2026-10-02T08:00:00"` |

**索引：**

| 索引名 | 字段 | 类型 | 说明 |
|---|---|---|---|
| ix_vitals_id | id | PRIMARY | 主键 |

> **注意**：A 当前未给 `elder_id` 和 `measured_at` 加复合索引。趋势查询是全表过滤后排序，数据量小不影响，M5 建议补充 `ix_vitals_elder_time (elder_id, measured_at)` 索引。

**枚举值：**

| 字段 | 取值 | 含义 | 使用字段 | 单位 | 正常参考范围 |
|---|---|---|---|---|---|
| type | `bp` | 血压 | systolic / diastolic | mmHg | 收缩压 90-140，舒张压 60-90 |
| type | `bs` | 血糖 | value | mmol/L | 空腹 3.9-6.1 |
| type | `hr` | 心率 | value | 次/分 | 60-100 |
| type | `weight` | 体重 | value | kg | BMI 18.5-24 |

**业务规则：**
- `type = "bp"` 时，`systolic` 和 `diastolic` 必填，`value` 为 NULL。
- `type` 为其他值时，`value` 必填，`systolic` 和 `diastolic` 为 NULL。
- `value` 字段在数据库中是 `VARCHAR(20)`（字符串），但接口 Schema `VitalsCreate` 中定义为 `float`，Pydantic 会自动转换。查询返回时 `VitalsOut` 中也是 `float | None`。
- 趋势接口 `/api/vitals/trend` 按天聚合，同一天多条记录取平均值。
- 列表接口默认查询最近 30 天（`days=30`），按 `measured_at` 倒序。

**与代码对应**：`db/models.py → class Vitals`  
**接口 Schema**：`VitalsCreate`、`VitalsOut`、`TrendPoint`

### 2.6 consult_records — 问诊记录表

**用途**：存储老人就诊录音文件及相关信息。

| 字段名 | 类型 | 约束 | 必填 | 说明 | 示例 |
|---|---|---|---|---|---|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | 是 | 记录ID | `1` |
| elder_id | INTEGER | FOREIGN KEY(users.id) NOT NULL | 是 | 所属老人ID | `1` |
| audio_url | VARCHAR(500) | NOT NULL | 是 | 录音访问路径（相对路径，如 `/api/consults/audio/xxx.mp3`） | `"/api/consults/audio/abc123.mp3"` |
| duration | INTEGER | NULLABLE | 否 | 录音时长（秒） | `320` |
| hospital | VARCHAR(100) | NULLABLE | 否 | 医院名称 | `"武汉市第一医院"` |
| doctor | VARCHAR(50) | NULLABLE | 否 | 医生姓名 | `"李医生"` |
| created_at | DATETIME | SERVER DEFAULT NOW() | 是 | 上传时间 | `"2026-10-02T15:00:00"` |

**索引：**

| 索引名 | 字段 | 类型 | 说明 |
|---|---|---|---|
| ix_consult_records_id | id | PRIMARY | 主键 |

**业务规则：**
- 录音文件存储在本地 `uploads/consults/` 目录，文件名用 UUID 避免冲突。
- `audio_url` 是相对路径，前端拼接 `http://host:port` 后通过 `GET /api/consults/audio/{filename}` 播放。
- 支持的音频格式：mp3、wav、m4a、aac（Content-Type 校验）。
- 当前未实现语音转文字（`transcript` 字段未在 models 中定义），录音仅做存储和回放。
- 列表按 `created_at` 倒序。

**与代码对应**：`db/models.py → class ConsultRecord`  
**接口 Schema**：`ConsultOut`

### 2.7 health_reports — 体检报告表

**用途**：存储体检报告图片、OCR 识别结果和 AI 健康建议。

| 字段名 | 类型 | 约束 | 必填 | 说明 | 示例 |
|---|---|---|---|---|---|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | 是 | 报告ID | `1` |
| elder_id | INTEGER | FOREIGN KEY(users.id) NOT NULL | 是 | 所属老人ID | `1` |
| image_url | VARCHAR(500) | NULLABLE | 否 | 体检单图片访问路径 | `"/api/reports/image/abc123.jpg"` |
| ocr_text | TEXT | NULLABLE | 否 | OCR 识别出的报告文字 | `"姓名：张某某 血压：145/90..."` |
| advice_text | TEXT | NULLABLE | 否 | AI 大白话建议（代码先精确判定指标，再 LLM 表达） | `"从报告看血压偏高..."` |
| created_at | DATETIME | SERVER DEFAULT NOW() | 是 | 上传时间 | `"2026-10-02T14:00:00"` |

**索引：**

| 索引名 | 字段 | 类型 | 说明 |
|---|---|---|---|
| ix_health_reports_id | id | PRIMARY | 主键 |

**业务规则：**
- 图片存储在本地 `uploads/reports/` 目录，文件名用 UUID。
- 支持的图片格式：jpg、png、webp。
- OCR 使用 `core/ocr.py`（PaddleOCR）识别图片文字。
- 指标判定使用 `core/report_parse.py` 的 `parse_metrics()` 函数精确判定每项正常/偏高/偏低，再由 `core/health_llm.py` 的 `report_advice()` 用大白话表达，避免 LLM 数值误判。
- **不做疾病诊断**，仅给出科普性质的健康建议。
- 列表按 `created_at` 倒序。

> **注意**：A 当前未在数据库中存储 `abnormal_items`（异常指标列表），异常指标仅在 OCR→解析→建议的流程中临时使用，不持久化。如果前端需要展示异常指标列表，需要 A 新增字段或从 `ocr_text` 中重新解析。

**与代码对应**：`db/models.py → class HealthReport`  
**接口 Schema**：`HealthReportOut`

### 2.8 symptom_checks — 症状自查记录表

**用途**：存储用户症状自查的输入和 AI 风险分级结果。

| 字段名 | 类型 | 约束 | 必填 | 说明 | 示例 |
|---|---|---|---|---|---|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | 是 | 记录ID | `1` |
| elder_id | INTEGER | FOREIGN KEY(users.id) NOT NULL | 是 | 所属老人ID | `1` |
| input_text | TEXT | NOT NULL | 是 | 用户输入的症状描述 | `"最近总是头晕，早上起来尤其明显"` |
| advice_text | TEXT | NULLABLE | 否 | AI 生成的建议 | `"您的症状可能与血压波动有关..."` |
| risk | VARCHAR(10) | NOT NULL | 是 | 风险等级 | `"yellow"` |
| created_at | DATETIME | SERVER DEFAULT NOW() | 是 | 查询时间 | `"2026-10-02T16:00:00"` |

**索引：**

| 索引名 | 字段 | 类型 | 说明 |
|---|---|---|---|
| ix_symptom_checks_id | id | PRIMARY | 主键 |

**枚举值：**

| 字段 | 取值 | 含义 | 前端展示 |
|---|---|---|---|
| risk | `green` | 低风险，可居家观察 | 绿色背景 |
| risk | `yellow` | 中风险，建议尽快就医 | 黄色背景 + 提醒 |
| risk | `red` | 高风险，立即就医/急诊 | 红色背景 + 大字警告 + 拨打120 |

**业务规则：**
- 风险分级由 `core/health_llm.py` 的 `symptom_advice()` 函数生成，返回 `(advice, risk)` 元组。
- 每次自查都会保存记录，方便家属查看历史。
- 列表按 `created_at` 倒序。
- `input_text` 不能为空（接口层校验）。

> **注意**：A 当前未在数据库中存储 `possible_causes`（可能原因）和 `recommended_actions`（建议行动），这些仅在 LLM 生成的 `advice_text` 中以文本形式存在。如果前端需要结构化展示，需要 A 新增字段或修改 `symptom_advice()` 返回结构。

**与代码对应**：`db/models.py → class SymptomCheck`  
**接口 Schema**：`SymptomCreate`、`SymptomOut`

## 六、安全与合规

1. **密码安全**：`password_hash` 使用 bcrypt 哈希（`core/security.py` 的 `hash_password()`），禁止明文存储。
2. **JWT 认证**：`core/security.py` 实现 `create_access_token()` 和 `get_current_user()`，所有需鉴权接口通过 `Depends(get_current_user)` 校验。
3. **越权控制**：每个健康模块都有 `resolve_elder_id()` 函数，家属必须与老人有 active 绑定才能操作。
4. **输入校验**：使用 Pydantic 模型（`db/schemas.py`）校验所有请求体，手机号用正则 `^1[3-9]\d{9}$`。
5. **文件上传校验**：录音和图片均校验 Content-Type，禁止上传非预期格式。
6. **医疗免责**：查药、体检报告等接口响应包含 `disclaimer` 字段（`core/disclaimer.py`），AI 提示词严格约束不做诊断和处方建议。
7. **SQL 注入防护**：全部使用 SQLAlchemy ORM 参数化查询。
