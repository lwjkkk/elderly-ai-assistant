## 一、设计原则

本产品的核心用户是 **60岁以上老年人**，所有设计决策必须围绕以下五个原则：

| 原则 | 说明 | 反面案例 |
|---|---|---|
| **看得清** | 字体足够大、对比度足够高、不使用浅灰小字 | 12号字、灰色文字、低对比度配色 |
| **听得懂** | 语言通俗、不用专业术语、句子简短 | "请配置您的个性化偏好设置" |
| **点得准** | 按钮足够大、间距足够宽、不使用小图标按钮 | 24px高的按钮、密集排列的小图标 |
| **学得会** | 操作流程简单、不超过3步、有明确的下一步引导 | 5层以上的嵌套菜单 |
| **有保障** | 出错有友好提示、有语音辅助、有家属兜底 | "Error 404"、"操作失败" |

## 二、字体规范

### 2.1 字号

| 元素 | 最小字号 | 推荐字号 | 说明 |
|---|---|---|---|
| 页面标题 | 24sp | 26-28sp | AppBar 标题 |
| 一级标题 | 22sp | 24sp | 卡片标题、模块标题 |
| 正文内容 | 20sp | 22sp | 主要文字、列表项 |
| 辅助文字 | 16sp | 18sp | 时间、备注、次要信息 |
| 按钮文字 | 20sp | 22-24sp | 所有可点击按钮 |
| 输入框文字 | 20sp | 22sp | 用户输入的内容 |
| 免责声明 | 14sp | 16sp | 底部常驻提示条 |

> **B 已实现**：`app_flutter/lib/main.dart` 中主题配置 `bodyLarge: 22sp`、`bodyMedium: 20sp`、`titleLarge: 26sp`，按钮文字 `22sp`。

### 2.2 字体选择

- **中文**：系统默认无衬线字体（Android: Roboto/思源黑体，iOS: 苹方）
- **数字**：等宽数字（tabular figures），体征数据展示时对齐
- **禁止**：使用艺术字体、手写字体、细体字（Light/Thin weight）

### 2.3 行高和字重

- 正文行高：**1.5倍**（避免文字拥挤）
- 标题行高：**1.3倍**
- 正文字重：**Regular（400）**或 Medium（500），不用 Light
- 标题字重：**Bold（700）**
- 按钮文字：**Bold（700）**

## 三、颜色与对比度

### 3.1 主色调

| 用途 | 色值 | 说明 |
|---|---|---|
| 主色 | `#2196F3`（蓝色） | 主要按钮、选中状态、链接 |
| 背景色 | `#F7F5EF`（米白） | 页面背景，比纯白更柔和 |
| 卡片背景 | `#FFFFFF`（纯白） | 卡片、输入框背景 |
| 主要文字 | `#212121`（近黑） | 标题、正文 |
| 次要文字 | `#616161`（深灰） | 辅助信息、备注 |
| 分割线 | `#E0E0E0`（浅灰） | 分割线、边框 |

> **B 已实现**：`main.dart` 中 `scaffoldBackgroundColor: Color(0xFFF7F5EF)`，`primarySwatch: Colors.blue`。

### 3.2 功能色

| 用途 | 色值 | 使用场景 |
|---|---|---|
| 成功/正常 | `#4CAF50`（绿色） | 体征正常、已服药、低风险(green) |
| 警告/注意 | `#FF9800`（橙色） | 体征偏高、中风险(yellow) |
| 危险/紧急 | `#F44336`（红色） | 高风险(red)、漏服、错误提示 |
| 信息 | `#2196F3`（蓝色） | 提示信息、天气提醒 |

### 3.3 对比度要求

- **正文文字与背景**：对比度 ≥ **4.5:1**（WCAG AA级）
- **大字号文字（≥18sp加粗或≥24sp）与背景**：对比度 ≥ **3:1**
- **按钮文字与按钮背景**：对比度 ≥ **4.5:1**
- **禁止**：浅灰文字配浅灰背景、白色文字配浅黄色背景

### 3.4 症状自查风险等级配色

| 风险等级 | 背景色 | 文字色 | 图标 |
|---|---|---|---|
| green（低风险） | `#E8F5E9`（浅绿） | `#2E7D32`（深绿） | ✅ |
| yellow（中风险） | `#FFF3E0`（浅橙） | `#E65100`（深橙） | ⚠️ |
| red（高风险） | `#FFEBEE`（浅红） | `#C62828`（深红） | 🚨 |

## 四、按钮与交互

### 4.1 按钮尺寸

| 类型 | 最小高度 | 推荐高度 | 最小宽度 | 圆角 |
|---|---|---|---|---|
| 主要按钮（确认/登录/提交） | 56dp | 56-64dp | 占满屏幕宽度（减padding） | 16dp |
| 次要按钮（取消/返回） | 48dp | 56dp | 占满屏幕宽度 | 16dp |
| 列表项点击区域 | 48dp | 56dp | 占满宽度 | - |
| 图标按钮（仅图标） | 48dp | 56dp | 48dp | 圆形 |

> **B 已实现**：`main.dart` 中 `ElevatedButton.styleFrom(minimumSize: Size(double.infinity, 56))`，圆角 `16dp`。

### 4.2 按钮间距

- 相邻按钮之间的垂直间距 ≥ **16dp**
- 按钮与上方内容的间距 ≥ **24dp**
- 页面底部按钮距离屏幕底部 ≥ **24dp**（避免误触系统导航栏）
- 同一行多个按钮之间间距 ≥ **12dp**

### 4.3 按钮状态

| 状态 | 视觉表现 |
|---|---|
| 正常 | 主色背景 + 白色粗体文字 |
| 按下（pressed） | 颜色加深10-15%，有涟漪效果 |
| 禁用（disabled） | 灰色背景（`#BDBDBD`）+ 深灰文字，不可点击 |
| 加载中（loading） | 按钮内显示圆形加载动画，文字变为"处理中…"，不可重复点击 |

### 4.4 点击反馈

- 所有可点击元素必须有**视觉反馈**（颜色变化、涟漪效果、缩放）
- 点击后 **100ms 内**必须有反馈（老年人会反复点击确认是否点中）
- 网络请求期间按钮禁用并显示加载状态，防止重复提交
- 重要操作（删除、解绑）需要**二次确认弹窗**

## 五、页面布局

### 5.1 页面结构

```
┌─────────────────────────┐
│   AppBar（标题+返回）     │  56dp
├─────────────────────────┤
│                         │
│   内容区域（可滚动）      │  弹性
│   - 卡片式布局           │
│   - 大间距               │
│   - 大字体               │
│                         │
├─────────────────────────┤
│   底部操作按钮（可选）    │  固定
├─────────────────────────┤
│   免责声明条（医疗页）    │  固定 36dp
└─────────────────────────┘
```

### 5.2 间距规范

| 元素 | 间距 |
|---|---|
| 页面左右边距 | 24dp |
| 卡片内边距 | 20dp |
| 卡片之间间距 | 16dp |
| 标题与正文间距 | 12dp |
| 表单项之间间距 | 16dp |
| 输入框与错误提示间距 | 8dp |
| 列表项之间间距 | 12dp（用分割线或卡片分隔） |

### 5.3 卡片设计

- 所有内容使用**卡片式布局**（白色背景 + 圆角16dp + 轻微阴影）
- 卡片阴影：`elevation: 2-4dp`，不要太重
- 卡片内信息层级清晰：标题（粗体大字）→ 正文 → 辅助信息（小字灰色）
- 可点击的卡片有点击反馈（按下时颜色变灰）

### 5.4 底部导航栏（Tab）

- 老人端 **5个Tab**：首页、办事助手、健康管理、我的、（语音悬浮球）
- 家属端 **4个Tab**：首页、老人健康、问诊记录、我的
- Tab 图标 + 文字，图标 ≥ 24dp，文字 ≥ 14sp
- 选中状态：主色图标 + 主色文字 + 底部指示条
- 未选中状态：灰色图标 + 灰色文字

## 六、输入框与表单

### 6.1 输入框规范

| 项目 | 规范 |
|---|---|
| 高度 | 56dp |
| 字号 | 22sp |
| 边框 | 1dp 灰色边框，圆角12dp |
| 聚焦状态 | 边框变为主色，2dp |
| 错误状态 | 边框变为红色，下方显示红色错误提示 |
| 标签文字 | 18sp，位于输入框上方（不是placeholder） |
| 提示文字（placeholder） | 18sp，浅灰色 |

### 6.2 表单设计原则

- **每个页面最多3-4个输入项**（如登录页只有手机号+密码）
- 输入项垂直排列，不并排（避免老年人看串行）
- 手机号输入框自动弹出**数字键盘**（`keyboardType: TextInputType.phone`）
- 密码输入框有**显示/隐藏**按钮（老年人容易忘记密码，需要能看到自己输入的）
- 表单提交按钮在页面底部固定，不需要滚动就能看到
- 错误提示用**大白话**，不用技术术语：
  - ✅ "手机号格式不对，请输入11位手机号"
  - ❌ "Invalid phone number format"

## 七、语音交互

### 7.1 语音输入

- 所有输入框旁边提供**麦克风按钮**（≥48dp），点击后语音转文字
- 语音输入时页面有明显的**录音状态提示**（红色麦克风动画 + "正在聆听…"文字）
- 支持普通话和**方言**（如果模型支持）
- 语音识别结果显示在输入框中，用户可以手动修改后再提交
- 录音超时：10秒无声音自动结束

### 7.2 语音播报（TTS）

- 所有 AI 回答内容支持**语音播报**（文字转语音）
- 播报按钮：≥48dp，喇叭图标，位于回答内容附近
- 播报语速：**慢速**（0.8-0.9倍速），老年人听得清
- 播报音量：默认最大音量的80%
- 播报时按钮变为暂停按钮，可随时暂停
- 播报结束后按钮恢复原状
- **医疗健康页面**默认自动播报关键提醒（可在设置中关闭）

### 7.3 语音悬浮球

- 老人端首页有**全局语音悬浮球**（≥56dp，圆形，主色）
- 点击悬浮球直接进入语音问答模式
- 悬浮球可拖动位置，避免遮挡内容
- 悬浮球有呼吸动画（透明度变化），提示用户"可以说话"

## 八、AI 回答的适老化要求

### 8.1 语言要求（A 已在 prompt.py 实现）

- ✅ 用"您"称呼用户，语气亲切，像跟长辈说话
- ✅ 不用专业术语，必须用时要解释
- ✅ 句子简短，每句不超过20字
- ✅ 步骤用"第一步、第二步、第三步"格式
- ✅ 按钮名称用「」标注，如：点击「我」
- ✅ 一次只讲一件事，不堆砌信息
- ✅ 结尾提醒："如果找不到按钮，可以问问身边的年轻人"
- ❌ 不用"请配置""请设置""请选择"等生硬指令
- ❌ 不用英文缩写（APP→应用、WiFi→无线网络、GPS→定位）

### 8.2 步骤要求

- 操作步骤 **3-5步**最合适，最多不超过6步
- 每步只描述**一个动作**，如"点击右下角「我」"
- 步骤按操作顺序排列，不跳步
- 如果步骤超过6步，拆分为多个页面或提示"先完成前3步，再继续"
- 关键步骤（如涉及支付、隐私）加粗或标红提醒

### 8.3 回答结构

```
【一句话总结】（先告诉用户结论）

第一步，……
第二步，……
第三步，……

【小提示】（可选，补充注意事项）

如果还有问题，可以问问身边的年轻人。
```

### 8.4 健康医疗类回答的特殊要求

- 先说明风险等级（低/中/高），再给建议
- 高风险情况第一句话就是"建议尽快就医"或"请立即拨打120"
- 不给出具体疾病诊断，用"可能与……有关"的表述
- 不推荐具体药品，用"请咨询医生或药师"
- 涉及用药时必须加免责声明

## 九、错误提示与异常处理

### 9.1 错误提示原则

- **不说技术术语**，用大白话解释发生了什么
- **告诉用户该怎么办**，不只是说"出错了"
- **语气友好**，不指责用户操作错误

### 9.2 常见错误提示文案

| 场景 | 推荐文案 | 禁止文案 |
|---|---|---|
| 网络断开 | "网络不太好，检查一下WiFi或移动数据，稍后再试" | "Network Error" / "连接超时" |
| 服务器错误 | "系统暂时出了点问题，稍后再试一次" | "500 Internal Server Error" |
| 登录失败 | "手机号或密码不对，再检查一下" | "Authentication failed" |
| 图片上传失败 | "图片上传没成功，换一张清楚的照片再试" | "Upload failed" |
| 录音权限未开 | "需要您允许使用麦克风，才能语音输入。去设置里打开吧" | "Permission denied" |
| 数据为空 | "还没有记录，点下面的按钮添加第一条吧" | "No data" / "Empty" |
| 操作成功 | "好的，已经帮您记下来了" | "Success" / "OK" |

### 9.3 加载状态

- 所有网络请求必须显示**加载动画**（圆形进度条 + "请稍候…"文字）
- 加载期间页面不可操作，防止重复点击
- 加载超时（30秒）后提示"响应太慢了，稍后再试"
- 列表加载用骨架屏（灰色占位块），不用空白页面

## 十、家属端特殊设计

### 10.1 家属端定位

家属端是给老人的子女使用的，用户相对年轻，可以适当提高信息密度，但仍需保持清晰易用。

### 10.2 家属端功能

- 查看绑定老人的健康数据（体征趋势、用药情况、体检报告）
- 代老人录入数据（用药、体征）
- 接收老人的健康提醒推送（漏服提醒、异常体征提醒）
- 查看问诊记录和症状自查历史

### 10.3 家属端展示要求

- 健康数据用**图表**展示（趋势曲线、统计数字），方便快速了解状况
- 异常数据用**红色高亮**标注
- 用药打卡情况用**日历热力图**或列表展示，漏服用红色标记
- 重要提醒（漏服、高风险症状自查）用**推送通知**告知家属
